## Una vulnerabilidad, cinco avisos

El único objeto de advisory en `via` es [GHSA-vfj7-8cjw-p6xm / CVE-2026-93687](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm), de `braces`. Los otros cuatro son avisos derivados por dependencia, no cuatro vulnerabilidades independientes.

| Paquete señalado           | Origen de su aviso                                |
| -------------------------- | ------------------------------------------------- |
| `braces`                   | Advisory directo: recursión sin límite suficiente |
| `micromatch`               | Depende de `braces`                               |
| `fast-glob`                | Depende de `micromatch`                           |
| `@next/eslint-plugin-next` | Depende de `fast-glob`                            |
| `eslint-config-next`       | Depende del plugin anterior                       |

El advisory describe agotamiento de pila por patrones de llaves profundamente anidados, incluso por debajo del límite de caracteres. Puede causar un `RangeError` y terminar el proceso Node si no se captura. No describe ejecución remota de código ni robo de secretos. npm lo clasifica como alto; la puntuación base no determina por sí sola la exposición de esta aplicación. El advisory consultado no publica versión corregida y `npm view braces version versions` confirma que 3.0.3 es la última disponible.

### Alcanzabilidad y riesgo residual

Se han leído los walkers recursivos en `braces/lib/compile.js` y `stringify.js` y el límite `MAX_LENGTH = 10000`; el límite de longitud no sustituye un límite de profundidad. No se ha ejecutado una prueba destructiva de agotamiento de pila: el advisory y el código bastan para este análisis, sin afectar procesos del usuario.

En el plugin instalado, `dist/utils/get-root-dirs.js` llama a `fast-glob.globSync` cuando `context.settings.next.rootDir` es un string o una lista. Sin esa opción usa `context.cwd` directamente. La configuración local no define `rootDir`, no obtiene patrones de peticiones ni tiene un servicio de lint accesible por red. Esta vía concreta no recibe patrones controlados por visitantes en el estado actual.

**Evaluación contextual:** riesgo de disponibilidad bajo en el desarrollo local actual; no se observa exposición a visitantes por esta cadena. El riesgo sigue existiendo si se introducen patrones no confiables, configuración externa, monorepos con globs, automatizaciones sobre contribuciones no confiables o herramientas que reutilicen `braces`. Revisar una contribución que modifique configuración ya supone una frontera de confianza: no debe asumirse segura por ser una dependencia de desarrollo. No hay CI configurada en esta entrega.

Medidas aplicables sin alterar funciones: mantener los patrones de herramientas bajo control del repositorio, revisar cambios de configuración antes de ejecutarlos y conservar las herramientas de desarrollo fuera de un futuro entorno de ejecución de producción. Esta última medida es una recomendación para el futuro; no se ha creado despliegue ni empaquetado de producción nuevo.

## ESLint 10 y reproducibilidad

La configuración flat carga Core Web Vitals y TypeScript de Next.js, coloca Prettier al final y excluye artefactos. El lint real pasa, pero `eslint-config-next` aceptar `eslint >=9` no hace compatibles todos sus plugins transitivos:

| Plugin efectivo y última versión consultada | Rango declarado de ESLint |
| ------------------------------------------- | ------------------------- |
| `eslint-plugin-import` 2.32.0               | `^2                       |     | ^3  |     | ^4  |     | ^5  |     | ^6  |     | ^7.2.0 |     | ^8    |     | ^9` |
| `eslint-plugin-jsx-a11y` 6.10.2             | `^3                       |     | ^4  |     | ^5  |     | ^6  |     | ^7  |     | ^8     |     | ^9`   |
| `eslint-plugin-react` 7.37.5                | `^3                       |     | ^4  |     | ^5  |     | ^6  |     | ^7  |     | ^8     |     | ^9.7` |

ESLint 10.13.0 queda fuera de esos tres rangos. `npm ls` termina con `ELSPROBLEMS`; `npm ci --dry-run --strict-peer-deps --ignore-scripts --no-audit --cache ../.npm-cache` falla con `ERESOLVE`. Esa comprobación fue una simulación y no sustituyó la instalación real.

La alternativa compatible con esos peers es ESLint 9.39.5, pero está fuera de mantenimiento desde el 6 de agosto de 2026 según [la política oficial de soporte](https://eslint.org/version-support/), y npm la marca obsoleta. No se sustituye una herramienta mantenida por otra EOL para ocultar avisos. Tampoco se alteran manualmente los rangos de terceros. Se mantienen ESLint 10 y la configuración actual con esta limitación explícita; un fallo futuro de una regla o un cambio de npm puede impedir trabajar aunque las comprobaciones actuales pasen.

La reproducibilidad se limita al entorno probado: Windows, Node.js 22.20.0 y npm 10.9.3 con resolución de peers por defecto. Un lockfile fija versiones y hashes, pero no garantiza compatibilidad con cualquier npm, sistema operativo o política estricta. No se ha añadido `.npmrc` para rebajar verificaciones.
